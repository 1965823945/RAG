Minimal RAG (Retrieval-Augmented Generation) Demo

Overview
- A tiny, end-to-end RAG workflow in Python using LangChain and ChromaDB.
- Day-by-day plan implemented with lightweight components and a Streamlit UI for demonstration.

Structure
- rag_minimal/Day1: LangChain hello world (no external API required).
- rag_minimal/Day2: PDF loading → chunking → embeddings → store in ChromaDB (10 docs).
- rag_minimal/Day3: Retrieval + prompt assembly + LLM (fake/local) → generate answer.
- rag_minimal/Day4: Streamlit UI with conversation history and live demo.
- Dockerfile: runs the Streamlit app for Day4.
- docs/pdfs/: generated sample PDFs for Day2 (generated by generate_samples.py).
- scripts/generate_samples.py: helper to create 10 sample PDFs when needed.

How to run (local)
- Day1: python -m rag_minimal.day1
- Day2: python rag_minimal.day2.py
- Day3: python rag_minimal.day3.py --question "Your question here"
- Day4: streamlit run rag_minimal/streamlit_app.py
- Day5: docker build -t rag-minimal .  && docker run -p 8501:8501 rag-minimal

Notes
- This is a minimal, self-contained example that prefers local, offline components to avoid API keys.
- If you have OpenAI API keys, you can switch to real embeddings and LLMs by adjusting the utils.
- CI-ready: a minimal GitHub Actions workflow is added at .github/workflows/ci.yml
- One-page startup guide at WorkSpace/RAG/WorkSpace/RAG/README_ONEPAGE.md
- Start scripts:
  * Docker: docker-compose up --build -d (via root docker-compose.yml or the one in WorkSpace/RAG/WorkSpace/RAG depending on how you structure)
  * Local: python WorkSpace/RAG/WorkSpace/RAG/run_all.py
