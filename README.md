Minimal RAG (Retrieval-Augmented Generation) Demo

Overview
- A concise, end-to-end RAG workflow in Python using LangChain and ChromaDB.
- A multi-phase implementation with a Streamlit UI for demonstration.

Structure
- rag_minimal/Phase1: LangChain hello world (no external API required).
- rag_minimal/Phase2: PDF loading -> chunking -> embeddings -> store in ChromaDB (10 docs).
- rag_minimal/Phase3: Retrieval + prompt assembly + LLM (fake/local) -> generate answer.
- rag_minimal/Phase4: Streamlit UI with conversation history and live demo.
- Dockerfile: builds and runs the Streamlit app for Phase4.
- docs/pdfs/: generated sample PDFs for Phase2 (generated by generate_samples.py).
- scripts/generate_samples.py: helper to create 10 sample PDFs when needed.

How to run (local)
- Phase1: python -m rag_minimal.Phase1.day1
- Phase2: python -m rag_minimal.Phase2.day2
- Phase3: python -m rag_minimal.Phase3.day3 --question "Your question here"
- Phase4: streamlit run rag_minimal.Phase4.streamlit_app.py
- Phase5: docker build -t rag-minimal .  && docker run -p 8501:8501 rag-minimal

Notes
- This is a minimal, self-contained example that prefers local, offline components to avoid API keys.
- If you have OpenAI API keys, you can switch to real embeddings and LLMs by adjusting the utils.
- CI-ready: a minimal GitHub Actions workflow is added at .github/workflows/ci.yml
- One-page startup guide at WorkSpace/RAG/README_ONEPAGE.md
- Start scripts:
  * Docker: docker-compose up --build -d (via root docker-compose.yml or the one in WorkSpace/RAG depending on how you structure)
  * Local: python WorkSpace/RAG/run_all.py
